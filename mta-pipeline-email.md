Hi Team,
I've built an automated approach to application modernization analysis using a two-phase method: Discovery via scripted automation, and Insights via AI skill-based reasoning.
________________________________________
Phase 1: Discovery (Script-Based)
A single PowerShell pipeline script automates the entire MTA analysis workflow:
•	Reads a CSV file containing all microservice components (CSI ID, git URL, branch)
•	Creates applications in MTA, links git credentials, and triggers containerization analysis — all in parallel
•	Waits for all components to complete, then generates structured CSV reports and downloads HTML reports
What used to take 30-45 minutes of manual UI work per application now runs in under 5 minutes for multiple components combined. The output is a clean, structured dataset of all mandatory findings across all components.
Phase 2: Insights (Skill-Based)
A Copilot instructions skill file (copilot-instructions.md) is auto-generated by the pipeline. This skill teaches GitHub Copilot how to interpret MTA analysis data. When we feed the discovery output into Copilot Chat, it provides:
•	Prioritized remediation plans grouped by component
•	Effort estimation in developer-days
•	Wave-based migration roadmaps (which component to containerize first)
•	Code-level fix patterns for each issue type
•	Executive summaries for leadership review
The skill ensures Copilot understands MTA-specific concepts like mandatory vs optional findings, effort scoring, containerization blockers, and migration target context
How the Two Phases Connect


CSV Input → [Script: Discovery] → Structured Findings → [Skill: Insights] → Actionable Intelligence
The script handles the heavy lifting of data collection. The skill handles the intelligence layer — turning raw findings into decisions.

What's Needed

apps.csv — list of components (fill once, reuse anytime)
mta-pipeline.ps1 — the discovery script
GitHub Copilot — for the insight layer (existing license)
No additional tools, no Python, no Docker — runs on standard VDI
Tested With

Retail Risk (5 components) — identified mandatory containerization blockers across all services
Customer Hub (6 components) — generated wave-based migration plan via Copilot in seconds

ur Method: MTA REST API (Server-Side)
The pipeline script calls the MTA server's REST API directly via PowerShell's Invoke-RestMethod:


PowerShell → HTTP requests → MTA Hub REST API (on OpenShift) → MTA server runs analysis
Authentication: Windows SSO (-UseDefaultCredentials)
Transport: HTTPS to https://mta-openshift-mta.apps.ilab-ctigtdc12d.ecs.dyn.nsroot.net/hub/...
Analysis runs on the server (OpenShift pods), not locally
Why Not CLI?
The CLI requires:
•	Installing the mta-cli binary (likely blocked on your VDI)
•	Source code cloned locally
•	Java runtime locally
•	Analysis runs on your machine (heavy)
The REST API approach:
•	Zero install (just PowerShell)
•	Analysis runs on the MTA server (OpenShift handles compute)
•	Works from restricted VDI
•	Same results as UI
